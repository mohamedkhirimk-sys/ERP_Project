# Invoice PDF Template Redesign — Design

Date: 2026-07-31
Status: Approved by user

## Overview

Restyle the invoice PDF generated by sales-service to match the French invoice template `modèle_de_facture.pdf` (7-column items table, TVA 20% with HT/TVA/TTC totals, Vendeur/Client blocks, meta table). Data model unchanged; only the PDF layout in `InvoicePdfService` and its unit tests change.

## Decisions

- Tax: invoice `totalAmount` is treated as **TTC**. Line HT = qty × unit price; line TVA = line HT × 20%; line TTC = line HT × 1.2. Total HT = Σ line HT; Total TVA = totalAmount − Total HT; **Total TTC = stored totalAmount** (authoritative)
- Seller block: keep the template's placeholder ("Mon Entreprise, 22, Avenue Voltaire, 13000 Marseille") for now
- Meta table includes only fields with data: Numéro de facture, Date (issuedAt), Échéance (dueDate), Statut. Paiement and Référence are dropped (no data)
- Unité column: `pcs` (all line items are products)
- Money: 2dp with `$` prefix (app-wide convention); line TVA/TTC scaled with RoundingMode.HALF_UP
- Fallback (unchanged behavior): product lookup failure → description = SKU, unit price "n/a", line total "—", line excluded from sums; PDF still generated

## Layout (A4)

1. Top-left: Vendeur block (placeholder company name + address)
2. Top-right: "FACTURE" title + meta table: Numéro de facture | Date | Échéance | Statut
3. Client block: name, email, phone, address
4. Items table — 7 columns: Description | Quantité | Unité | Prix unitaire HT | % TVA | Total TVA | Total TTC
5. Totals block (right-aligned): Total HT | Total TVA | Total TTC
6. Footer: generated timestamp (small, grey)

## Scope

- Modify: `InvoicePdfService.java` (layout + TVA math)
- Modify: `InvoicePdfServiceTest.java` (assertions for new content)
- No controller/API/frontend changes
